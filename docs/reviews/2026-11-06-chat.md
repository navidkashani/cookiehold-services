# Chat and support review — 2026-11-06

Twelve permanent IDs reviewed: ten corrected and two unresolved. Each
correction has a limited scope; remaining questions are recorded below.

## Scope and consumer impact

Reviewed provider, purpose, privacy URL, processing locations, persistence,
address patterns, Consent Mode and WordPress hints. Vendor descriptions of
cookies as necessary do not determine a site's legal basis. Categories,
legal bases, placeholders and Consent Mode flags are unchanged. These are
not Google tags merely because they integrate with other analytics tools.

All IDs, address/inline patterns and WordPress hints are preserved. Two
storage patterns are added: `intercom.intercom-state-*` and
`_livechat_has_visited`. Neither overlaps another service's storage patterns.
Removing the former can discard cached Messenger state. The latter is
documented on LiveChat's frame origin; listing it does not give a parent
page access to that origin. No shared authentication or generic storage
keys are added. No translations are generated.

Location corrections omit the previous parenthetical DPF labels: these
fields describe geography, and this review does not newly certify program
participation. Omission is not a claim that a vendor withdrew from the DPF.

## crisp

Outcome: **corrected**, version 3 → 4, with unresolved findings.

The [infrastructure explanation](https://help.crisp.chat/en/article/crisp-eu-gdpr-compliance-status-nhv54c/)
identifies Crisp IM SAS, EU message/plugin storage and relay servers in the
USA, UK and Singapore that retain connection logs. Add those relay locations
to the existing Netherlands/Germany wording. EU primary storage is not the
whole processing footprint.

confirms the existing prefix and six-month default; the
[SDK cookie guide](https://docs.crisp.chat/guides/chatbox-sdks/web-sdk/cookie-policies/)
documents configurable expiry. Change the lifetime to “6 months by default.”
The WordPress source emits the existing `CRISP_WEBSITE_ID` marker.
New guidance explains Total Privacy mode's delayed session initialization,
without promising that loading the script makes no requests.

Unresolved: the policy retains older, more absolute IP-retention prose beside
newer session-specific wording. Obtain a reconciled retention statement
before turning that prose into additional catalog facts. Optional AI and
integration configurations require their own processor review; no generic
claim that every Crisp feature is EU-only is made.
