compatibility certification. Unresolved questions remain attached to each ID,
including those with supported corrections.

Consent Mode and WordPress hints. Existing categories and legal bases are
catalog decisions, not legal conclusions established by vendor documents.

aliases or storage wildcards are added. No translations are generated.

## shopify-buy-button

Outcome: **corrected**, version 1 → 2, with unresolved findings.

The [privacy policy](https://www.shopify.com/legal/privacy) identifies the
Irish affiliate for EEA visitors and processing in Canada, the USA and other
locations. Expand the location field accordingly. The
[delivered Buy Button SDK](https://sdks.shopifycdn.com/buy-button/latest/buy-button-storefront.min.js)
still writes `_shopify_y` and `_shopify_s`. Its persistent max-age is
62,208,000,000 milliseconds, or 720 days; correct “2 years” to “720 days.”
The session-identifier max-age remains 1,800,000 milliseconds (30 minutes).
The writer adds these intervals to the current time when writing expiry.

The broader [Shopify cookie policy](https://www.shopify.com/legal/cookies)
now lists other storefront identifiers; do not replace this embed's inventory
from that table alone. The [Buy Button guide](https://help.shopify.com/en/manual/online-sales-channels/buy-button/create-buy-button)
supports new guidance about replacing embed code after appearance changes
and choosing the checkout window behavior.

Unresolved: the SDK also writes generic `_y`/`_s` aliases and stores a checkout
ID using a key constructed from a storefront token and domain. The schema
only supports trailing wildcards; there is no safe universal prefix for that
key. Broadening generic aliases risks recognizing unrelated cookies, and
clearing cart storage affects cart continuity. Keep those detection changes
pending fixtures and consumer review. Inspect hosted checkout separately.

## woocommerce-attribution

Outcome: **corrected**, version 3 → 4, with unresolved findings.

The [attribution documentation](https://woocommerce.com/document/order-attribution-tracking/)
confirms the stored order information and listed cookie durations. It also
states that opting into [WooCommerce usage sharing](https://woocommerce.com/usage-tracking/)
sends statistical attribution data to Automattic per order. Thus “Stays on
this website” is not universally true. Replace it with conditional hosting/
international-processing wording, supported by
[Automattic's transfer policy](https://automattic.com/privacy/).

The released [11.2.2 consent integration](https://plugins.svn.wordpress.org/woocommerce/tags/11.2.2/src/Internal/Integrations/WPConsentAPI.php)
uses the marketing signal when WP Consent API is active. Guidance explains
the feature switch, the integration's scope and retention of past order
information. This is vendor behavior, not a claim that CookieHold has been
tested with it. The [attribution controller](https://plugins.svn.wordpress.org/woocommerce/tags/11.2.2/src/Internal/Orders/OrderAttributionController.php)
registers that integration.

Unresolved: the single provider field still names the site running the
feature. Conditional attribution of optional usage sharing to the appropriate
Automattic/WooCommerce entities needs a deliberate provider-model decision;
the policy describes multiple controllers. Do not invent one exclusive legal
recipient. The site operator's hosting location cannot be inferred here.
